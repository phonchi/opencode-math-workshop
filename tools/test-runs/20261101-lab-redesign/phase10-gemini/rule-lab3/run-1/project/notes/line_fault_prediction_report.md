# 產線故障預測模型分析報告

## 1. 專案概述與目標
本專案旨在利用產線紀錄 `data/line_faults.csv` 中的感測器數據（溫度、震動、壓力、流量、電流、轉速）來預測設備是否會發生故障（`fault`）。評估模型是否具備上線生產環境（Production）的價值。

## 2. 資料探索與預處理決策（未要求之自主決策）
- **資料集規模**：共 900 筆樣本，包含 6 個數值特徵與 1 個目標標籤 (`fault`)，無遺漏值。
- **類別不平衡處理**：
  - 正樣本（故障 `fault=1`）僅 71 筆，佔總數約 $7.89\%$。
  - 為了避免模型偏向多數類（正常狀態），在訓練時採用類別權重調整（Logistic Regression 的 `class_weight='balanced'`、XGBoost 的 `scale_pos_weight`）以強化對少數故障類別的識別能力。
- **資料分割**：
  - 採用 $80\%$ 訓練集與 $20\%$ 測試集進行評估（`test_size=0.2`, `stratify=y`），確保訓練與測試集中的故障比例一致。
- **特徵標準化**：
  - 針對邏輯迴歸（Logistic Regression）進行了 `StandardScaler` 標準化處理；樹模型則保持原始數值。

## 3. 模型評估與比較
我們評估了四種機器學習模型（透過 5 折交叉驗證）：

| 模型 | ROC-AUC | F1-Score | Recall (靈敏度) | Precision (準確率) |
| :--- | :---: | :---: | :---: | :---: |
| **Logistic Regression** | **0.9525** | **0.5463** | **0.9303** | **0.3885** |
| **Random Forest** | 0.9332 | 0.5074 | 0.4879 | 0.5503 |
| **Gradient Boosting** | 0.9345 | 0.3687 | 0.2939 | 0.5410 |
| **XGBoost** | 0.9318 | 0.5282 | 0.5394 | 0.5367 |

在測試集（Test Set）上，表現最佳的 **Logistic Regression** 模型指標如下：
- **Accuracy**：$90.56\%$
- **Precision**：$0.4483$
- **Recall**：$0.9286$（成功抓出超過 $92\%$ 的真實故障）
- **F1-Score**：$0.6047$
- **ROC-AUC**：$0.9781$
- **PR-AUC**：$0.8824$

數學上，分類器的決策邊界公式為：
$$P(y=1 | X) = \sigma(w^T X + b) = \frac{1}{1 + e^{-(w^T X + b)}}$$

透過調整決策閾值（Threshold），可以在誤報成本與漏報成本之間取得平衡。

## 4. 能否上線評估（Deployment Assessment）

**結論：可以上線，但建議作為「輔助預警系統（Early Warning System）」而非全自動停機控制。**

### 支援上線的理由：
1. **極高的召回率（Recall = 92.86%）**：在產線環境中，漏掉故障（False Negative）可能導致設備無預警損壞、產線停擺或安全事故，其成本遠高於誤報。模型能抓出絕大多數的潛在故障。
2. **優異的鑑別力（ROC-AUC = 0.978）**：模型在區分正常與異常狀態上表現非常穩健。

### 上線時需要注意的限制與改善建議：
1. **誤報率較高（Precision = 44.83%）**：約有一半的警報為誤報（False Positive）。若直接連動自動停機，會造成產能損失。建議設定為「通知維修人員進行人工復核」。
2. **門檻調校**：可根據實際廠房的經濟成本函數（漏報成本 $C_{FN}$ 與誤報成本 $C_{FP}$）動態調整機率輸出閾值：
   $$\text{Cost} = C_{FN} \cdot (1 - \text{Recall}) \cdot N_{fault} + C_{FP} \cdot (1 - \text{Precision}) \cdot N_{normal}$$
3. **即時監控與特徵工程**：上線時需確保感測器數據（`temp_c`, `vibration_mm_s`, 等）具備即時清洗與標準化管道。

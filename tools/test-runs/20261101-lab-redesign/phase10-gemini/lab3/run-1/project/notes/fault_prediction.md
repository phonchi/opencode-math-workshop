# 產線故障預測模型評估報告

## 1. 資料集摘要
- **總樣本數**：900 筆記錄
- **特徵**：`temp_c` (溫度), `vibration_mm_s` (震動), `pressure_kpa` (壓力), `flow_lpm` (流量), `current_a` (電流), `speed_rpm` (轉速)
- **標籤**：`fault` (0: 正常, 1: 故障)
- **類別分佈**：正常樣本 829 筆 (92.1%)，故障樣本 71 筆 (7.9%)，屬於明顯的類別不平衡 (Class Imbalance)。

## 2. 模型效能評估
使用隨機森林 (Random Forest) 進行 5 折交叉驗證 (Stratified 5-Fold Cross-Validation)：

### (A) 預設模型 (Threshold = 0.5)
- **ROC-AUC**：$0.928$
- **故障類別 (Fault = 1)**：
  - 精確率 (Precision)：$0.83$
  - 召回率 (Recall)：$0.27$
  - F1 分數 (F1-score)：$0.40$
- **評語**：雖然 ROC-AUC 高達 $0.928$，但 Recall 僅 $0.27$，代表模型會**漏掉 73% 的真實故障**，不適合直接上線。

### (B) 類別平衡與閾值優化模型 (`class_weight='balanced'` + 最佳化閾值 $0.54$)
- **ROC-AUC**：$0.930$
- **故障類別 (Fault = 1)**：
  - 精確率 (Precision)：$0.59$
  - 召回率 (Recall)：$0.52$
  - F1 分數 (F1-score)：$0.55$
- **評語**：透過調整類別權重與決策閾值，Recall 提升至 $52\%$，但仍有一半的故障無法被偵測，且誤報率提升（Precision $59\%$）。

## 3. 重要特徵分析 (Feature Importance)
根據隨機森林特徵重要性排序：
1. `temp_c` (溫度)：$35.4\%$
2. `vibration_mm_s` (震動)：$18.8\%$
3. `pressure_kpa` (壓力)：$13.9\%$
4. `speed_rpm` (轉速)：$13.5\%$
5. `flow_lpm` (流量)：$9.6\%$
6. `current_a` (電流)：$8.8\%$

## 4. 能不能上線用？（上線建議）

- **直接自動化上線（停機/攔截）**：**不行**。
  目前模型在故障偵測上的 Recall 偏低（即使調參後也僅 52%），在產線環境中會造成嚴重的漏報（False Negatives），導致設備突發故障損壞。
- **輔助預警系統（通知工程師人工複查）**：**有條件可行**。
  若將其作為「產線健康預警看板」，提醒操作員針對高風險機台進行加強巡檢，可作為輔助工具。但必須向團隊說明其存在約 48% 的漏報率與 41% 的誤報率。

### 後續優化建議
1. **累積更多故障數據**：目前故障樣本僅 71 筆，數據量偏少，模型泛化能力受限。
2. **特徵工程**：加入時間序列滾動特徵（Rolling Mean / Std）、滑動窗口變異數等，捕捉設備漸進式老化的趨勢。
3. **嘗試其他演算法**：測試 XGBoost、LightGBM 或不平衡學習演算法（如 SMOTE、Isolation Forest）。

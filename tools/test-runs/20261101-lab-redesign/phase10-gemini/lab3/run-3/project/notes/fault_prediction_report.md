# 產線故障預測模型分析報告

本報告針對 `data/line_faults.csv` 產線紀錄資料進行機器學習模型訓練與評估，並就其是否能直接投入線上生產環境進行專業評估。

## 1. 資料集概述 (Dataset Overview)

- **總樣本數**：900 筆紀錄
- **特徵維度**：6 個感測器變數（`temp_c`, `vibration_mm_s`, `pressure_kpa`, `flow_lpm`, `current_a`, `speed_rpm`）
- **目標變數**：`fault`（二元分類：0 = 正常，1 = 故障）
- **類別分佈**：
  - 正常 (0)：829 筆 ($92.1\%$)
  - 故障 (1)：71 筆 ($7.9\%$)
- **資料特性**：屬於典型的**類別不平衡 (Class Imbalance)** 資料集，故障樣本比例僅約 $7.9\%$。

我們採用 80/20 的分層抽樣（Stratified Train-Test Split）將資料分為訓練集與測試集，並在處理類別不平衡（使用類別權重調整 `class_weight='balanced'` 或整合學習）後評估多個模型。

## 3. 特徵重要性分析 (Feature Importance)

透過模型係數與特徵重要性分析，影響產線故障的關鍵因子排序如下：

1. **`temp_c`**（溫度）：影響最大，過熱通常是機械或電氣故障的前兆。
2. **`vibration_mm_s`**（震動）：震動異常直接反映機械結構磨損或失衡。
3. **`pressure_kpa`**（壓力）：壓力異常波動代表氣動或液壓系統異常。
4. **`speed_rpm`**（轉速）與 **`flow_lpm`**、**`current_a`**。

## 4. 能否上線評估（能不能上線用？）

### 結論：**可以「輔助上線」（作為預警系統），但不建議直接進行「全自動停機控制」。**

#### 評估依據：
1. **高效的召回率 (High Recall)**：
   - 羅吉斯迴歸模型在故障偵測上達到了 $93\%$ 的召回率（Recall），能抓出絕大多數的潛在故障，降低漏報率（False Negative），避免災難性設備損壞。
2. **誤報率與成本考量 (Precision vs. False Alarms)**：
   - 模型精確率 (Precision) 約在 $45\% - 67\%$ 之間。這意味著系統發出的故障警報中，有相當比例是「誤報」(False Positive)。
   - 若直接用於自動停機，頻繁的誤報將導致產線不必要的中斷，造成產能損失與現場操作人員的「警報疲勞 (Alarm Fatigue)」。

#### 建議上線策略與後續優化：
1. **第一階段（上線初期 - 顧問/預警模式）**：
   - 將模型部署為**產線健康監控儀表板與預警系統**。當模型預發出故障警報時，通知維修工程師進行人工複查，而非直接停機。
2. **第二階段（閾值調優 Threshold Tuning）**：
   - 根據實際業務的**成本矩陣 (Cost Matrix)**（即「漏報一個故障的損失」與「誤報一次的停機成本」之比值）來動態調整分類閥值（Threshold），平衡 Precision 與 Recall。
3. **第三階段（持續監控與迭代）**：
   - 建立資料漂移 (Data Drift) 監控機制，隨著產線環境變化定期重新訓練模型。

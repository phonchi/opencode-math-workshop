# 產線故障預測模型筆記

## 資料
- `data/line_faults.csv`：900 筆，7 個感測器特徵 + `record_id` + `fault`
- 類別極度不平衡：故障 71 筆（7.9%），正常 829 筆
- 無缺失值

## 關鍵發現：資料漂移（drift）
- 故障的 `record_id` 平均 38，正常的平均 486 → 故障**全部集中在資料前段**（前 ~70 筆）
- 這代表兩件事：
  1. `record_id` 是時間代理，絕不能當特徵。若用隨機切分 + record_id 建模，PR-AUC = 1.000（完美洩漏），上線後無效。
  2. 若按時間切分，測試集**零故障**、無法評估 → 產線後段疑似已改善或故障型態改變，模型學到的是「早期設備狀態」的故障模式。

## 模型評估（分層隨機切分 70/30，僅用感測器特徵）
| 模型 | PR-AUC | ROC-AUC |
|---|---|---|
| Logistic Regression（balanced） | **0.767** | 0.970 |
| RandomForest | 0.484 | 0.927 |

主要訊號：`temp_c`（+3.0）、`vibration_mm_s`（−2.0）、`pressure_kpa`（+1.3）、`speed_rpm`（+0.7，標準化係數）。故障樣本溫度偏高、振動偏低。

閾值取捨（測試集 21 筆故障）：
- 召回 0.81 / 精確率 0.57（閾值 0.739）：漏抓 4 筆，13 次誤報
- 召回 0.90 / 精確率 0.42（閾值 0.576）：漏抓 2 筆，26 次誤報

## 上線建議：**暫不建議直接上線**
理由：
1. 洩漏示範顯示 record_id 能完全分離故障 → 故障與時間強相關，模型實際能力被樂觀偏差高估
2. 測試集故障樣本僅 21 筆，估計不穩（PR-AUC 95% CI 很寬）
3. 後段資料零故障，無法驗證模型在目前產線狀態下是否有效

若要上線，建議：
- 重新收集**近期**帶標籤資料（尤其目前運轉條件下的故障樣本）
- 上線前用時間序驗證（近期資料當 holdout）
- 先以「預警參考」模式運行（通知工程師，不自動停機），監控誤報率

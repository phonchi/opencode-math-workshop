課前準備

請在工作坊前完成安裝與下方自測。第一次建立環境需要下載套件，請找網路穩定的地方操作；最後看到程式產生檔案並印出結果，就準備好了。

先確認一件事：你會用終端機嗎

這場工作坊全程在終端機裡進行。如果你平常只在 VS Code 按執行鍵、 或只用過 Google Colab，先跟著下面的操作認識它。

終端機入門：打開它、走到資料夾、確認位置

終端機就是一個「用打字下指令」的視窗。它永遠站在某一個資料夾裡面， 你打的指令都是對那個資料夾下的。這件事最重要，也最常被忽略。

Linux / WSLLinux 開啟 Terminal；WSL 從 Windows 開始選單開啟已安裝的 Ubuntu

路徑是資料夾的位置

Git Bash 的路徑通常像 /c/Users/你的名字/Documents/ai-math-lab，對應 Windows 的 C:\Users\你的名字\Documents\ai-math-lab；WSL 像 /home/你的名字/ai-math-lab。請選一個環境完成本教材，同一份虛擬環境不要在兩邊交替使用。路徑含空格時，把整段路徑放在雙引號裡。

例如在 Git Bash 輸入 cd ~/Documents/ai-math-lab，其中 ~ 代表你的使用者資料夾；請換成自己的實際位置。接著依序輸入 pwd 和 ls，確認位置與檔案。

每一種文字該貼在哪裡

看到 uv sync、opencode 這類指令，貼到 Git Bash 或 macOS／Linux／WSL 的終端機，按 Enter 執行（用 Ctrl+V 或 Shift+Insert 貼上）。進入 OpenCode 後，才貼「請幫我……」的任務。程式的預期輸出用來比對，不用貼回終端機。多個步驟請逐步執行，確認上一個步驟完成再繼續。

整場工作坊最常見的錯誤

在錯的資料夾裡啟動 opencode。這樣它可能找不到你的 AGENTS.md 與 opencode.json，無法沿用本課程的模型與執行規則。 每次啟動前先用 pwd 跟 ls 確認位置。

幾個小技巧

  • Tab 鍵會自動補完檔名與資料夾名。打前幾個字母按 Tab，省事又不會打錯
  • ↑ 方向鍵叫回上一個指令，不用重打
  • 指令卡住停不下來：Ctrl+C
  • 畫面太亂：打 clear
  • Windows 的 Git Bash 字太小：按 Ctrl 加 + 放大、Ctrl 加 - 縮小、Ctrl 加 0 還原。只滾滑鼠滾輪不會縮放

這場工作坊只會用到這些終端機操作。

安裝

Windows

從官方網站安裝 Git

開啟 Git for Windows 官方下載頁，下載並執行安裝檔（.exe）。 安裝畫面保留預設選項，一路按 Next，最後按 Install；跳出權限視窗時選「是」。

開啟 Git Bash，安裝 opencode 與 uv

從開始選單搜尋並開啟 Git Bash，依序貼上這三行：

touch ~/.bash_profile
curl -fsSL https://opencode.ai/v2/install | bash
curl -LsSf https://astral.sh/uv/install.sh | sh

第一行建立 Git Bash 的設定檔。少了它，opencode 的安裝程式找不到地方記錄路徑，重開後會找不到 opencode。

讓 Python 正確輸出中文

在同一個視窗執行一次，之後不用再設定：

setx PYTHONUTF8 1

繁體中文 Windows 上的 Python 預設不一定用 UTF-8 輸出，少了這一步，OpenCode 裡看到的中文可能變成亂碼。

讓 OpenCode 可以用 Ctrl+V 貼上

同樣只要執行一次：

printf 'KeyFunctions=C+v:paste\nShootFoot=on\n' >> ~/.minttyrc

這行讓 Git Bash 視窗自己處理 Ctrl+V。少了它，在 OpenCode 裡按 Ctrl+V 可能貼不上文字。

關掉 Git Bash，再重新開啟

新裝的程式與環境變數不會出現在已經開著的視窗裡。重開後才往下走；之後的指令與 opencode 都在 Git Bash 裡執行。

macOS

先開「終端機」確認 Git。如果還沒安裝，macOS 會跳出視窗請你安裝 Command Line Tools，照畫面完成即可：

git --version

macOS 內建 curl，接著貼這兩行：

curl -fsSL https://opencode.ai/v2/install | bash
curl -LsSf https://astral.sh/uv/install.sh | sh

（macOS 請依官方安裝說明操作，課前完成同一份自測；需要協助時提早聯絡講師。）

Linux / WSL

這裡要多一個步驟。Git 與下載工具 curl 不一定裝在你的系統裡， Ubuntu 的基本安裝不一定包含它們。真正一定有的是套件管理員 apt， 所以先用它補上： 

sudo apt update && sudo apt install -y git curl ca-certificates

（ca-certificates 是驗證 HTTPS 憑證用的，少了它 curl 會連不上。 如果這些本來就有，這行也只會告訴你「已經是最新版」，不會弄壞任何東西。）

接著才裝 opencode 與 uv：

curl -fsSL https://opencode.ai/v2/install | bash
curl -LsSf https://astral.sh/uv/install.sh | sh

裝完後關掉終端機重開，或執行 source ~/.bashrc。

確認裝好了

git --version
opencode --version
uv --version

三個指令都應印出版本號；記下來，之後求助時可以一起提供。opencode --version 要是 v2 開頭（例如 opencode v2.2.7）。如果你之前裝過 1.x 版，重跑一次上面的安裝指令就會換成 V2。

如果出現「找不到指令」

先確認終端機能讀到安裝後的新路徑。把終端機完全關掉、重新開一個再試。 還是不行的話，Windows 請確認開的是 Git Bash，不是 PowerShell 或 cmd。

開啟狀態列

狀態列會一直顯示在 OpenCode 畫面最底下，告訴你 context 用了多少、回應速度和經過時間。Lab 3 會用它記 context 用量。這是第三方外掛 opencode-status-line，只支援 V2。三個平台都在終端機貼上同一段：

mkdir -p ~/.config/opencode
cat > ~/.config/opencode/cli.json <<'EOF'
{
  "$schema": "https://opencode.ai/v2/cli.json",
  "plugins": ["@rashidrazak/opencode-status-line"]
}
EOF

如果你本來就有 ~/.config/opencode/cli.json，上面這段會把它整個蓋掉。這時改用編輯器打開它，只在 "plugins" 裡加上 "@rashidrazak/opencode-status-line"。

要等下面建好專案、啟動 opencode 並送出一句話後，底部才會出現狀態列。輸入 /tps 可以看詳細統計。

用任何文字編輯器建立一個叫 pyproject.toml 的檔案。Windows 可在 Git Bash 輸入 notepad pyproject.toml，用記事本建立後存檔；後面兩個檔案也一樣。內容：

建立 opencode.json

同一個資料夾，建立 opencode.json：

{
  "$schema": "https://opencode.ai/config.json",
  "model": "opencode/big-pickle",
  "provider": {
    "nvidia": {
      "models": {
        "z-ai/glm-5.3-flash": {
          "options": { "reasoningEffort": "low" }
        }
      }
    }
  },
  "permission": {
    "bash": "ask",
    "edit": "ask",
    "webfetch": "ask"
  },
  "agent": {
    "plan": { "permission": { "edit": "deny", "bash": "deny" } }
  },
  "instructions": ["AGENTS.md"]
}

中間的 provider 只在你切到備案模型 GLM-5.3-Flash 時才有作用。少了它，這個模型會推理很久，同一題可能從幾十秒拖到十幾分鐘。

為什麼放在專案裡而不是全域設定

opencode 的設定是一層一層疊上去的：全域設定 → 專案設定，後者蓋掉前者的同名項目。 把工作坊的設定放在專案資料夾裡，就不會影響你電腦上其他的 opencode 用途， 換一個資料夾就換一套設定。

OpenCode 的設定檔放在哪裡？
位置放什麼
全域：~/.config/opencode/
（Windows 是 C:\Users\你的名字\.config\opencode）		opencode.json 或 opencode.jsonc（可寫註解）：所有專案共用的設定
cli.json：介面設定與介面外掛，例如上面的狀態列
專案：專案資料夾裡的 opencode.json
或 .opencode/opencode.json		只對這個專案有效的設定，例如本課程的模型與權限
~/.local/share/opencode//connect 存的 API key 和對話紀錄。不要分享，也不要放進 Git

同一個設定兩邊都有時，專案的蓋過全域的；.opencode/ 裡的又蓋過專案根目錄的。想知道 OpenCode 實際讀到哪些設定檔，在專案資料夾執行 opencode debug config。

詳細規則見官方的設定文件。

建立 AGENTS.md

這是給 agent 看的專案規則。課前只放操作規則和「Plan 模式先一次問一題」；課程結束時，你會把今天學到的追問寫成規則加回來。同一個資料夾，建立 AGENTS.md：

# AI-Math 工作坊　專案規則

## 語言
一律使用台灣繁體中文回答。程式碼、變數名稱、套件名稱保留英文。

## 執行環境
本專案用 uv 管理環境。執行 Python 一律用：`uv run python <檔案>`
不要用 `python`、`python3`、`pip install`。要加套件用 `uv add <套件>`。

## 規劃（Plan 模式）
在 Plan 模式收到任務時，先不要列計畫。一次只問我一個問題，並附上你建議的答案，最多問 3 題。問清楚後，再列出計畫和你打算替我做的決定。

## 圖檔
所有圖存到 `figs/`，用 `savefig()`，不要用 `plt.show()`（它可能開視窗並等待關閉，程式看起來像卡住）。

## 筆記
筆記寫在 `notes/` 底下的 .md 檔，數學式用 $...$ 與 $$...$$。

## 不要做的事
- 不要 git commit 或 git push，除非我明講。
- 不要刪除 `figs/` 或 `notes/` 裡既有的檔案。

建立 Python 環境（這步會等比較久）

uv sync

第一次執行會下載 Python 與套件，請等指令完成，回到可輸入下一個指令的提示字元。

如果超過一分鐘還在跑，去泡杯茶。看到類似這樣就對了：

uv sync

+ pandas==3.1.1
+ scipy==1.18.1
+ scikit-learn==1.9.1

+ networkx==3.6.1
（還有十幾個相依套件）

綠燈自測

下面三個測試全部通過，你就準備好了。

測試一：Python 環境

uv run python -c "import numpy, pandas, scipy, sklearn, matplotlib, networkx; print('環境 OK')"

應該印出 環境 OK。如果中文是亂碼，回到安裝步驟確認 setx PYTHONUTF8 1 已執行，並重開 Git Bash。

測試二：agent 會回話

opencode run "用一句話說明什麼是主成分分析"

應該得到一段繁體中文的回答。

測試三：agent 真的會動手（最重要的一關）

opencode run --auto "建立一個 hello.py，內容是印出 1 到 10 的平方，然後執行它"
那個 --auto 是什麼，為什麼只有這裡要加

你剛才在 opencode.json 裡把 edit 和 bash 設成 ask， 意思是「agent 要改檔案或跑指令之前，先問過我」。

問題是 opencode run 是非互動模式，沒有人可以回答那個問題。 opencode 的處理方式是直接拒絕： 

! permission requested: edit (hello.py); auto-rejecting
✗ Write hello.py failed
Error: This non-interactive run cannot ask the user for permission, so the request was rejected.

--auto 就是「這一次我事先全部答應」。 它在自測時很方便，但平常不要養成習慣。 工作坊全程我們都用互動模式（直接打 opencode）， 那時候每個動作都會停下來問你，你才有機會看清楚它要做什麼。

預期畫面
> build · big-pickle
← Write hello.py
$ uv run python hello.py
1 1
2 4
（中間省略）
10 100
已建立 hello.py 並用 uv run python hello.py 執行完成。

看到 ← Write（寫檔）和 $（執行指令），代表 agent 能動手。 它用了 uv run python，不是 python，表示你的 AGENTS.md 規則有生效。

如果測試二或測試三出現 Free usage exceeded，代表免費額度暫時用完了，不是你裝錯。先完成下一節，再用備案模型確認能回話。

準備備案 key

big-pickle 這類免費模型的額度，是按對外 IP 和日期計算，上限也會變動。教室全班共用校園 Wi-Fi，可能很快就用完。 請在課前申請好兩把免費 key；上課時一樣先用 big-pickle，不能用才照下面的順序換。

順序模型什麼時候用注意
1big-pickle預設不用登入
2其他免費模型，例如 beam-freebig-pickle 額度用完用 /models 切換；可能和 big-pickle 一起被擋
3Gemini 3.5 Flash Lite免費模型都不能用要自己的 Gemini key
4GLM-5.3-FlashGemini 也不能用要自己的 NVIDIA key；比較慢，但一樣能完成三個 Lab
申請前請先看
  • 要滿 18 歲。Gemini API 條款要求滿 18 歲，NVIDIA 條款要求達法定成年。未滿 18 歲請不要申請，先告訴講師。
  • 送出的內容可能被用來改進產品，也可能有人工審閱。只用課堂的練習資料，不要送未發表研究、個人資料或機密內容。
  • 每人用自己的帳號。額度是按專案計算的，共用 key 會一起用完。
  • 不要綁信用卡或設定帳單。如果畫面要求付款，先停下來問講師。
  • key 就像密碼。不要貼到聊天室、截圖、opencode.json 或 Git。

申請 Gemini key

開啟 Google AI Studio 的 API key 頁面，建議用個人 Gmail 登入並接受條款。頁面上已經有 key 就直接複製；沒有就按 Create API key。學校帳號可能沒有建立權限。

申請 NVIDIA key

開啟 build.nvidia.com，點開任一個模型，按右側的 Get API Key。輸入 email 按 Next，完成註冊或登入後，按 Copy Key 複製。

註冊時要用手機收簡訊驗證碼，有時會等很久或收不到，所以請在課前就申請。等了幾分鐘還沒收到，先跳過這一步，上課時告訴講師；你還有 Gemini 可以用。

把 key 連到 OpenCode

在專案資料夾輸入 opencode，然後在 OpenCode 裡操作：

  1. 輸入 /connect 按 Enter，打 Google 按 Enter，貼上 Gemini key 按 Enter。
  2. 接著會跳出模型清單。打 Flash Lite，選 Gemini 3.5 Flash Lite；出現 variant 選單時，選 Default 按 Enter。
  3. 確認左下角顯示 Gemini 3.5 Flash Lite，輸入 1+1 等於多少？只回答數字，應該收到回答。
  4. 再做一次 /connect：打 NVIDIA，貼上 NVIDIA key，模型選 GLM-5.3-Flash，variant 同樣選 Default，再問一次同樣的問題。
  5. 輸入 /exit 離開。

key 會存在這台電腦的 OpenCode 設定裡，之後不用再貼。每次重開 OpenCode 都會回到 big-pickle，上課要用備案時，用 /models 再選一次即可。

上課時可能看到的訊息
  • high demand 或 way too hot：Google 暫時過載，OpenCode 會自動重試，先等一下。等超過一分鐘還沒恢復，就換下一個模型。
  • Quota exceeded for metric：先看後面寫的是哪種額度。每日請求（per day）用完就換下一個模型；每分鐘的上限等一下再試。
  • Gemini 模型請選 Gemini 3.5 Flash Lite。Gemini 3.6 Flash 每天只有約 20 個請求，一堂課不夠用。
  • 畫面底部的 $0.01 是估算的費用。只要沒有設定帳單，就不會收費。
  • Gemini 偶爾會把英文思考過程混進回答，這不影響程式執行。

兩個備案都能完成讀檔、寫檔和執行。Gemini 3.5 Flash Lite 同一天免費層每天上限 500 個請求（Google 回傳的額度），每人用自己的專案；GLM-5.3-Flash 的開場和三個 Lab 各跑 3 次。全班同時使用的情況還沒測過，額度也可能變動。

curl: command not found Linux/WSL 沒有內建 curl 先跑 sudo apt update && sudo apt install -y git curl ca-certificates，再重跑安裝指令。
Error: Internal server error 看不到真正原因 加旗標重跑：opencode run "..." --print-logs --log-level ERROR
Unrecognized request argument supplied: prompt_cache_key opencode 的已知上游問題，偶發 重試一次通常就好。仍然失敗就保留錯誤訊息，請講師協助。
Free usage exceeded 免費額度暫時用完 等待沒有用。照備案順序換模型。
換成其他模型後回 UnknownError 或 API key is missing 那個模型的 key 還沒連好，或不是課程指定的模型 只用備案順序裡的模型，需要 key 的先做 /connect。不要改 opencode.json 裡的 model。
uv sync 下載很慢或中斷 網路 重跑一次，uv 會接續已下載的部分，不會從頭來。
permission requested: edit ...; auto-rejecting opencode run 是非互動模式，沒人能回答 ask 的權限詢問 自測時加 --auto。平常請用互動模式（直接打 opencode）。
agent 用了 python 而不是 uv run python AGENTS.md 沒被讀到 確認 AGENTS.md 跟 opencode.json 在同一個資料夾，且你是在那個資料夾裡啟動 opencode。
還是不行的話

把你打的指令和完整的錯誤訊息截圖，工作坊開始前傳給助教。 請不要只說「裝不起來」，那樣沒辦法幫你。

最後提醒

免費模型會看你送過去的內容

opencode/big-pickle 是限時免費的試用模型，官方明講資料可能被用於改進模型；Gemini 和 NVIDIA 的免費服務也一樣。 不要把未發表的研究資料、個人隱私資料或任何機密內容丟進去。 課堂用的都是為這堂課造的合成資料，沒有這個問題。
